## Things to know for the viva (not changed)

- The lifecycle triggers (deposit before CONFIRMED, status order) fire on UPDATE only, so an INSERT can create an order in any status. The generator relies on this to load history. A production system would add INSERT checks.
- Streaming replication here is asynchronous, so a very recent write can briefly be missing on the replica (the lag line shows how long).
- P4 design documents are generated independently of the PostgreSQL orders (order ids 1 to 40,000 are used as keys, but occasion and branch are random). In production they would be built from the real order.
